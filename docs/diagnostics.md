# Diagnostics

Every problem is reported as a diagnostic with a stable code, a severity, a message, and when available a location (file, JSON pointer, line and column), the operation it relates to and a hint. Codes are stable across patch releases; `--json` output includes them for tooling.

- **error** — generation stops and nothing is written.
- **warning** — output is generated; something was ignored, interpreted or may not match the specification exactly.
- **info** (notes) — shown with `--verbose`.

The CLI exits with `2` when an error is a configuration problem (`config/*`) and with `1` for other errors. Terminal output shows control characters from the specification or plugins as `\xNN` escapes; `--json` output contains the text unchanged (JSON-escaped).

## Lint findings

`swaggerz lint` reports the diagnostics above plus findings with the code `lint/<rule>`. Their severity is the rule's default unless `lint.rules` sets another one (or `'off'`).

| Code                      | Default | Meaning                                                                                                        |
| ------------------------- | ------- | -------------------------------------------------------------------------------------------------------------- |
| `lint/operation-id`       | warning | An operation has no `operationId`: its function name is derived from the method and path and changes with them |
| `lint/operation-id-style` | info    | An `operationId` is not an identifier in the `naming.operations` style: the exported function has another name |
| `lint/operation-tags`     | info    | An operation has no tags: it is generated into the `default` group                                             |
| `lint/undeclared-tag`     | info    | A tag used by operations is not declared in the top-level `tags`                                               |
| `lint/operation-summary`  | info    | An operation has neither a summary nor a description for its JSDoc                                             |
| `lint/success-response`   | warning | An operation documents no 2xx or `default` response: it resolves with `void`                                   |
| `lint/response-schema`    | warning | A JSON success response has no schema: the operation resolves with `unknown`                                   |
| `lint/inline-schema`      | info    | A JSON request or response body is an inline object schema, named after the operation and not reusable         |
| `lint/untyped-schema`     | info    | A named schema has no type, properties or composition: it is generated as `unknown`                            |
| `lint/duplicate-schema`   | info    | Named schemas are structurally identical: the client contains duplicate types                                  |
| `lint/unused-model`       | info    | A named schema is not used by any operation (still generated unless `output.models: 'used'`)                   |
| `lint/missing-servers`    | info    | No server is declared and `client.baseUrl` is not set: the client has no default base URL                      |
