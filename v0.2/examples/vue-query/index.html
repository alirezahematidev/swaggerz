    05Project

    Vue Query example

    The task list of the React Query example, built with Vue 3 single-file components, TanStack Vue Query and Valibot validation, from the same OpenAPI 3.1 document (openapi.yaml).

    Or, inside this directory once swaggerz is built:

    What to look at:

    • swaggerz.config.ts enables Vue Query composables (features.query.framework: 'vue'), an infinite list for listTasks paginated by its cursor parameter, invalidation of every Tasks query after mutations, and Valibot validation of responses.
    • vite.config.ts adds swaggerz() from swaggerz/vite: the client is generated when Vite starts, again whenever openapi.yaml or swaggerz.config.ts changes (edit the specification while pnpm dev runs and the page updates, or shows the error over it), and before vite build. There is no separate generate step. See framework integrations.
    • src/App.vue passes a getter as the parameters of useListTasksInfinite, so changing the filter refetches; src/TaskDetails.vue does the same with a prop and uses select. Errors are typed: ApiError with the operation’s error body (Problem) or RequestError.
    • src/mocks.ts serves the API in the browser with the generated Mock Service Worker handlers: fixtures (makeTask) seed an in-memory list that the handlers read and change. src/main.ts passes those handlers to the generated startMocks() during development only (one line: if (import.meta.env.DEV) await startMocks({ handlers })); vite.config.ts serves the worker script with MSW’s Vite plugin. It is typed with the generated models, so it stops compiling when the specification changes. See mocks.
